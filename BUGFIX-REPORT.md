## 0. Три наблюдаемых бага (как их описывает пользователь)

При запросе генерации Word-файла в разделе «Чат с ИИ» ответ приходит карточкой файла
(стикер Вишенки + карточка документа + текст + кнопки «Скачать» / «Поделиться»). Баги:

1. **«Поделиться» шлёт ССЫЛКУ на сломанную страницу вместо самого .docx.**
   Требование: нажатие «Поделиться» должно открывать окно контактов Telegram (или системное
   окно шаринга с другими мессенджерами) для пересылки **строго WORD-файла**. Никаких ссылок.
2. **«Скачать» не открывает файл на экране.** Требование: файл должен **скачаться И открыться**
   на экране.
3. **Тап по WORD-файлу или по стикеру Вишенки над ним не скачивает и не открывает файл.**
   Требование: тап = скачивание + открытие.

## 2. БАГ 1 — «Поделиться» отправляет ссылку вместо файла

### 2.1. Что происходит сейчас

Цепочка в `chShare` (index.html:2132):

1. `A.shareFile(u,x.n,mime)` — если это APK: системное окно пересылки с файлом. ✅ верно.
2. `tg.shareMessage(r.id, ...)` после `api("/api/chat_file/prepare",{tok})` (Telegram ≥ 8.0):
   родное окно «Отправить в…», контакт получает сам .docx. ✅ верно.
3. `navigator.canShare` → `navigator.share({files:[f]})` — браузер шарит файл. ✅ верно.
4. **ЗАПАСНОЙ ПУТЬ — `chShLink(u,x)` (index.html:2130):**
   ```js
   const l="https://t.me/share/url?url="+encodeURIComponent(u)+"&text=encodeURIComponent("Word-документ: "+x.n);
   try{tg.openTelegramLink(l)}catch(e){window.open(l,"_blank")}
   ```
   ❌ **ВОТ БАГА:** `t.me/share/url` открывает окно «Отправить в…», но в сообщение кладёт
   **ССЫЛКУ** на `/api/chat_file/{tok}?tok={подпись}`, а не файл. Получатель видит ссылку.
5. Ещё один источник ссылки — строка ниже в `chShare`:
   `navigator.share({title:x.n, url:u})` — тоже шарит **URL**, а не файл. ❌

### 2.2. Почему ссылка «сломанная»

- Ссылка подписная и **живёт 30 минут** (`CHAT_FILE_TTL`, bot.py:2092). Через полчаса
  `api_chat_file` отвечает 404 «Файл устарел» — получатель открывает «сломанную страницу».
- Даже в течение 30 минут получатель — не владелец: `check_chat_file_token` привязывает
  подпись к tg_id отправителя; чужой вход получает 403 (bot.py:2145).
- То есть ссылка неизбежно ведёт на пустую/отказную страницу — ровно то, что видит пользователь.

### 2.3. Поведение, которого хотим (контракт)

Нажатие «Поделиться» → открывается окно пересылки, где выбирается **контакт Telegram или
другой мессенджер на устройстве**, и пересылается **строго файл .docx**. Ни одного пути,
который кладёт в сообщение ссылку.

### 2.4. План исправления

**Фронт (`chShare`, index.html:2132–2149) — новая цепочка, ссылки запрещены полностью:**

1. APK (`window.Android.shareFile`) → системный chooser с файлом — уже работает, оставить первым.
2. Telegram ≥ 8.0 (`tg.shareMessage` + `/api/chat_file/prepare`) — уже работает, оставить вторым.
   При отказе `shareMessage` (callback `false`) — **не** падать на ссылку, а двигаться дальше.
3. Браузер/WebView с Web Share API Level 2: `navigator.canShare({files})` →
   `navigator.share({files:[new File([blob], x.n, {type:mime})]})` — системное окно с файлом.
4. **Крайний случай (единственный легальный фолбэк без ссылки):** файл скачивается и
   показывается тост/попап «Файл сохранён — перешлите его из «Загрузок» / прикрепите к чату».
   (Как вариант — бот-копия в чат Telegram, откуда штатный «⋮ → Переслать».)

**Удалить/запретить:**
- функцию `chShLink` (index.html:2130) целиком;
- `navigator.share({title:x.n, url:u})` (шаринг URL);
- любой `t.me/share/url` из html (заодно поправить контракт теста, см. §5).

**Сервер:** `/api/chat_file/prepare` (bot.py:2165) уже готовит `InlineQueryResultDocument` с
`document_url` на подписной файл — менять не требуется. При желании добавить retry/log.

**Telegram API (сверено с core.telegram.org/bots/webapps, Bot API 8.0+):**
- `Telegram.WebApp.shareMessage(preparedMessageId, callback)` — «Отправить в…», файл;
  события `shareMessageSent` / `shareMessageFailed`.
- `PreparedInlineMessage` получается через Bot API `savePreparedInlineMessage` — уже реализовано.

## 3. БАГ 2 — «Скачать» не открывает файл на экране

### 3.1. Что происходит сейчас

`chDl` (index.html:2122–2128):

1. APK: `A.shareFile(...)` — **открывает окно шаринга**, а не просмотр документа (нет ACTION_VIEW).
2. Telegram ≥ 8.0: `tg.downloadFile({url, file_name, mime_type})` — нативный попап скачивания;
   **файл скачивается, но не открывается** (`downloadFile` по документации только сохраняет;
   событие `fileDownloadRequested` отдаёт `status: downloading|cancelled` — открытия нет).
3. Браузер: `<a download>` — только скачивание.

### 3.2. Поведение, которого хотим (контракт)

Нажатие «Скачать» → файл **скачивается И открывается на экране**.

### 3.3. План исправления

**APK — новая функция JsBridge `openFile(url, name, mime)` в `MainActivity.java`:**
- скачать через `DownloadManager` (как в `startShare`, строка 571);
- затем `Intent.ACTION_VIEW` с `content://` URI скачанного файла (URI от DownloadManager
  или FileProvider по образцу `CaptureProvider`) + `FLAG_GRANT_READ_URI_PERMISSION`,
  mime = mime параметра (docx → `application/vnd.openxmlformats-officedocument.wordprocessingml.document`);
- если нет приложения-просмотрщика — chooser с тостом «Нет приложения для открытия .docx».
- `chDl` и `chFileTap` при наличии `A.openFile` зовут его (скачать+открыть);
  `A.shareFile` остаётся строго для кнопки «Поделиться».

**Мини-апп (Telegram WebView) — честные ограничения платформы:**
`tg.downloadFile` скачивает, но **Telegram не даёт веб-странице открыть docx на экране**
(нет API открытия локального файла). Реальные варианты:
- «Скачать» → `tg.downloadFile` → после подтверждения показать попап «Файл скачан —
  откройте его в «Загрузках» / нажмите на файл в чате с ботом» (копия уже уходит в чат Telegram,
  см. `api_chat` bot.py:2313 — там файл приходит документом, и тап по нему в Telegram
  открывает его штатным просмотрщиком Telegram);
- альтернатива: скачать через fetch→Blob и открыть `window.open(blobUrl)` — для .docx
  браузер всё равно скачает, не отрисует; как «открытие на экране» не годится, использовать только
  как усиление скачивания.
Итог: в APK открытие на экране — полное (ACTION_VIEW); в Telegram — скачивание + прямая подсказка
вскрыть файл из чата с ботом (единственный канал, где Telegram умеет показать docx).

## 4. БАГ 3 — тап по файлу/стикеру не скачивает и не открывает

### 4.1. Что происходит сейчас

`chFileTap(i,j,e)` (index.html:2083–2086) вызывается и с `fc-stk` (стикер Вишенки), и с `fc-doc`
(карточка документа) — см. `chFc`, строки 2101–2102:

1. APK: `A.shareFile(...)` — открывается **окно шаринга**, а не скачивание+открытие. ❌
2. Иначе: `tg.openLink(u)` — открывает **ссылку на страницу файла в браузере** (та самая
   подписная страница, через полчаса — «Файл устарел»), скачивание не запускается. ❌
3. Возврат `true` оставляет обычный переход по `<a href>` — уходит на URL файла, тот же эффект.

### 4.2. Поведение, которого хотим (контракт)

Тап по WORD-файлу или по стикеру Вишенки над ним → **скачивание + открытие WORD-файла**
(то же, что кнопка «Скачать» из §3).

### 4.3. План исправления

- `chFileTap` должен вести ровно в ту же функцию «скачать+открыть», что и `chDl`
  (вынести общую `chOpen(i,j)` / `chOpenFile(x)`):
  - APK → `A.openFile(...)` (§3.3);
  - Telegram → `tg.downloadFile(...)` + подсказка (§3.3);
  - браузер → fetch→Blob→`<a download>` (скачивание), при возможности открыть.
- `e.preventDefault()` всегда — чтобы `<a href>` не уводил на подписную страницу.
- Оставить `chFileTap` кликабельным для обоих элементов (уже так: `fc-stk` и `fc-doc`,
  index.html:2101–2102) — правится только поведение.

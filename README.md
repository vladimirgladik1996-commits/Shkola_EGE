# Бот репетитора + мини-апп

Telegram-бот и мини-апп (Telegram Web App) для репетитора: расписание с
длительностью занятий, ученики, оплаты, автоматический расчёт долгов,
регулярные занятия и печать недели в PDF.

- **Бот** — ведение расписания через кнопки Telegram (`aiogram`).
- **Мини-апп** — «Кабинет»: сетка недели, карточки дней, оплаты, печать.
- **Backend** — один процесс `bot.py`: бот + HTTP-сервер (`aiohttp`).

---

## Быстрый старт

1. Создайте бота в @BotFather, получите токен. Telegram ID — у @userinfobot.
2. `pip install -r requirements.txt`
3. Мини-аппе нужен публичный https. Для теста: `cloudflared tunnel --url http://localhost:8080` (или ngrok).
4. Заполните окружение (см. `.env.example`) и запустите:

```bash
export BOT_TOKEN="***"
export OWNER_ID=111222333
export WEBAPP_URL=https://ваш-адрес
export CURRENCY=₽        # необязательно
python bot.py
```

5. Откройте бота → `/start` → кнопка «Кабинет».

Подробные сценарии деплоя (MVP, Pages + отдельный backend, сервер) — в [`DEPLOY.md`](DEPLOY.md).

## Архитектура

**Одно-доменное приложение.** `bot.py` — это одновременно Telegram-бот и
HTTP-сервер, который раздаёт:

| Путь | Что отдаёт |
|---|---|
| `GET /` | страницу мини-аппа (`docs/index.html`) |
| `GET/POST /api/*` | JSON API мини-аппа |
| `GET /api/week.pdf` | PDF недели |

Мини-апп ходит в API **по относительным путям** (один домен) и передаёт
заголовок `X-Init` с Telegram `initData`.

```
Telegram ──► bot.py (aiogram) ──► SQLite (tutor.db)
                  │
                  └── aiohttp :8080
                        ├── GET  /            → docs/index.html
                        └── /api/*            → тот же код, что и бот
                              ▲
                              │ HTTPS + X-Init (initData)
                        Telegram Mini App (docs/index.html)
```

### Авторизация

1. Мини-апп шлёт `initData` Telegram в заголовке `X-Init`.
2. Backend проверяет HMAC-подпись `initData` секретным ключом = **токен бота**.
3. Доступ есть **только у `OWNER_ID`** — кабинет однопользовательский.

`GitHub Pages` умеет только статику: он не запустит Python и не отдаст `/api/*`.
Поэтому «залить на Pages» недостаточно — нужен запущенный backend с публичным
HTTPS (см. DEPLOY.md).

## Логика бота (`bot.py`, ~750 строк)

Разделы файла сверху вниз:

| Раздел | Что делает |
|---|---|
| **БД** | подключение SQLite, `CREATE TABLE IF NOT EXISTS`, авто-миграция старых баз (`ALTER TABLE`), хелперы `q()` / `run()` |
| **Логика занятий** | `conflict()` — проверка пересечений по времени; `fill_regular()` — дозаполнение серии на 12 недель вперёд; `add_lesson / move_lesson / cancel_lesson / stop_series / make_regular` |
| **Баланс** | `stats()`, `balance_text()`: `баланс = Σоплат − (проведённые занятия × цена)`; `update_student`, `update_payment`, `delete_payment` |
| **PDF** | `week_pdf(start)` — неделя в A4 альбомом через reportlab + DejaVu; шлётся как файл |
| **Клавиатуры** | `menu_kb`, `dates_kb`, `time_kb`, `mode_kb`, `dur_kb`, `students_kb`, `amount_kb`, `price_kb` |
| **Состояния (FSM)** | `NewStudent`, `CustomTime`, `Pay` — многошаговые сценарии ввода |
| **Хендлеры** | `make_lesson` и обработчики сообщений/колбэков |
| **HTTP** | `api_*` обработчики + `web.Application`, CORS с `ALLOW_ORIGIN` |

Порядок создания занятия в боте: **ученик → дата → время → длительность → разовое/регулярное**.

Сценарии, которые понимает бот:

- **Регулярные**: «Сделать регулярным» ставит то же время на тот же день недели
  каждую неделю; расписание держится на **12 недель вперёд** и дозаполняется само.
  - «Отменить это занятие» → убирает одно занятие серии (в `skips`).
  - «Перенести» → двигает только выбранное занятие.
  - «Прекратить серию» → удаляет это и все следующие.
  - Если слот в какую-то неделю занят другим учеником — повтор пропускается, о чём бот сообщает.
- **Точное время**: кнопки 08:00…20:00 или «🕐 Своё время» → ввод `ЧЧ:ММ`.
- **Длительность**: 30/45/60/90/120 мин. Пересечения запрещены.

## Логика мини-аппа (`docs/index.html`, ~250 строк)

Один файл, vanilla JS, без сборки. Экраны:

| Экран | Что делает |
|---|---|
| **Расписание** | сетка «время × 7 дней», блоки по минутам и длительности; кнопка «🖨 Распечатать» → предпросмотр A4 |
| **Карточка дня** | тап по дню → занятия дня + «+ Добавить занятие» |
| **Форма занятия** | ученик / новый ученик, дата, время (любые минуты), длительность чипами, «Повторять каждую неделю» |
| **Оплаты** | общая статистика, фильтры «Все / Должники / Предоплата», лента поступлений, ✏️ правка/удаление платежа, «График» — круговая диаграмма |
| **Ученики** | список с аватарами и статусом; карточка: фото, ФИО, проведённые занятия, оплачено, баланс, последние 5 платежей |
| **PDF** | «Поделиться PDF»: Web Share API (файлом), иначе бот пришлёт PDF в чат |

Ключевые функции:

| Функция | Роль |
|---|---|
| `api(path, body)` | все вызовы backend; добавляет `X-Init` |
| `load()` → `ingest()` | получение состояния и нормализация в `S` (ученики), `L` (занятия), `P` (платежи) |
| `demoData()` | **демо-режим**: если API недоступен (например, только Pages), рисуются примерные данные + тост «Демо-режим — данные примерные» |
| `grid() / sched()` | отрисовка недельной сетки |
| `form() / save() / del()` | создание/перенос/отмена занятий |
| `sharePdf()` | запрос `/api/week.pdf` и передача файла |

`API_BASE` — пустая строка, если фронт и API на одном домене; иначе
`window.__API_BASE__="https://<backend>"`.

### API контракт

Все запросы требуют заголовок `X-Init` (Telegram `initData`). Тело — JSON.

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| GET | `/` | — | `docs/index.html` |
| GET | `/api/data` | — | `{students, lessons, payments, cur}` |
| GET | `/api/week.pdf?start=YYYY-MM-DD` | — | PDF |
| POST | `/api/week/send` | `{start}` | отправляет PDF в чат владельцу |
| POST | `/api/lesson/add` | `{student_id \| name, day, time, dur, regular}` | занятие |
| POST | `/api/lesson/move` | `{id, day, time, dur}` | занятие |
| POST | `/api/lesson/cancel` | `{id}` | отмена одного занятия |
| POST | `/api/lesson/regular` | `{id}` | сделать регулярным |
| POST | `/api/lesson/stop` | `{id}` | прекратить серию |
| POST | `/api/student/add` | `{name, price}` | ученик |
| POST | `/api/student/update` | `{id, name, price, photo}` | ученик |
| POST | `/api/payment/update` | `{id, amount}` | платёж |
| POST | `/api/payment/delete` | `{id}` | удаление платежа |

## Схема БД (SQLite, `tutor.db`)

```sql
students (id, name, price, photo)                  -- цена занятия, аватар
lessons  (id, student_id, day, time,
          regular_id, dur, UNIQUE(day, time))      -- день YYYY-MM-DD, время HH:MM
payments (id, student_id, amount, created)         -- created = datetime('now','localtime')
regular  (id, student_id, weekday, time, start, dur) -- серия: день недели + время
skips    (regular_id, day, PRIMARY KEY(...))       -- пропущенные повторы серии
```

`day` — строка `YYYY-MM-DD`, `time` — строка `HH:MM`, `dur` — минуты (60 по умолчанию).

### Как считается долг

`баланс = Σ платежей − (количество проведённых занятий × цена ученика)`

Занятие считается проведённым, когда его время наступило.
`баланс < 0` — долг, `> 0` — оплата наперёд.

### Миграции

Старая база открывается без ручных действий: `ALTER TABLE` добавляют
`lessons.regular_id`, `students.photo`, `lessons.dur`, `regular.dur`; у существующих
занятий `dur = 60`.

## Функции (детали)

### Печать недели
«Расписание» → «🖨 Распечатать» — предпросмотр A4: сетка «время × 7 дней» текущей
недели с именами учеников. «Поделиться PDF»: если телефон умеет делиться файлами —
откроется меню приложений; иначе бот пришлёт PDF в чат. PDF строится на сервере
(reportlab), шрифт DejaVu лежит в `fonts/`.

### Печатная форма
Лист A4 альбомной ориентации, рассчитан на чёрно-белую печать: у пустых часов —
нейтральная серая заливка строки, у занятых — белая ячейка с жирной чёрной полосой
слева. Ничего не завязано на цвет ученика, поэтому при печати без цвета ничего не
«сливается». Имя — крупным жирным, регулярные занятия помечены «повтор».
Дни недели — полными названиями (Понедельник…Воскресенье) с датой.

### Точное время занятия
Кнопки-часы (08:00…20:00) остаются быстрым способом, но есть и точное время с
минутами (8:25, 14:40):
- **В боте:** на шаге выбора времени кнопка «🕐 Своё время» → ввод `ЧЧ:ММ`.
- **В мини-аппе:** под списком часов — «Указать точное время» → нативный выбор часов/минут.

Расписание, печатная форма и PDF поддерживают это полностью: если время не ровно час,
над именем ученика показывается точное время.

### Длительность и временная сетка
У занятия длительность 30–120 мин. Неделя, печать и PDF рисуются временной сеткой:
начало блока — по минутам, высота — по длительности. Пересекающиеся занятия сохранить
нельзя (в т.ч. в регулярной серии — такое повторение пропускается).

## Окружения: dev и prod

Разделение — **через переменные окружения и ветку**, а не через код.
Шаблоны: [`env/dev.example`](env/dev.example) и [`env/prod.example`](env/prod.example).

| | **dev** | **prod** |
|---|---|---|
| Ветка | `dev` | `main` |
| Фронт | `python bot.py` отдаёт `GET /`, либо `docs/index.html` локально | GitHub Pages → `docs/` на `main` |
| URL фронта | `cloudflared` / `ngrok` туннель | `https://<user>.github.io/Shkola_EGE/` |
| `WEBAPP_URL` | адрес туннеля | адрес Pages |
| `ALLOW_ORIGIN` | пусто (всё с одного домена) | `https://<user>.github.io` |
| Backend | локально, `PORT=8080` | сервер (Docker) с HTTPS |
| БД | `./data/tutor.db` (можно удалить) | `./data/tutor.db` + бэкапы |
| Данные | тестовые / демо | живые ученики и платежи |
| Демо-режим фронта | активен, если API недоступен | выключен (API на месте) |

### Правила

1. `.env` **никогда** не коммитится (в `.gitignore`). Только `*.example`.
2. Токен бота — только на сервере / в секретах хоста, не в чат и не в код.
3. В `main` попадает только проверенное; разработка идёт в `dev`.
4. `docs/` на `main` — это прод-фронтенд. Любая правка в `docs/` на `main`
   сразу видна пользователям.

### Как переключиться

```bash
# dev
git checkout dev
cp env/dev.example .env      # заполнить
python bot.py

# prod
git checkout main
cp env/prod.example .env     # заполнить на сервере
docker compose up -d --build
```

## Запуск через Docker

```bash
cp env/prod.example .env   # заполнить
docker compose up -d --build
```

`docker-compose.yml` монтирует `./data:/app/data` — там живёт `tutor.db`,
поэтому данные переживают пересборку образа.

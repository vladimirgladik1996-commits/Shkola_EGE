# 018 — «ИИ-проверка»: прелоадер врёт, нет фото с разметкой, PDF с обрывками и кривой вёрсткой

Дата: 2026-11-02 · Прод: tutor-bot-y40k · Прогон-доказательство: 05:51–05:54 UTC (logs: `yavision: слов=55`,
`essaycheck: слов=40 ... балл=0/8`, `essayreport: движок html, pdf 757 КБ`)

## Причины

1. **Прелоадер врёт про задание/опорный текст.** `EC_STAGES` — статичный список этапов, рисуется целиком
   независимо от загруженного (`w=1 t=0` → этап «Прочитано задание и опорный текст» всё равно был на экране).
   Плюс строка этапа «Проверены орфография и пунктуацию» не совпадала со статусом стрима
   «Проверяю орфографию, пунктуацию, грамматику и речь» — этап никогда не закрывался.
2. **В превью нет фото с разметкой ошибок.** (а) `ecPhotoMode()` требовал координаты у ВСЕХ ошибок
   (`every(x,y)`), а координаты есть только у ошибок, чей фрагмент нашёлся в словах OCR — фото-режим
   не включался никогда; (б) `ecPhotoDesk` подставлял в `<img src>` объект `ecShots.w[p]` вместо
   `ecShots.w[p].src` → `[object Object]`, фото не могли отрисоваться в принципе.
3. **PDF: обрывки текста вместо работы.** Фото пережималось дважды: клиент canvas JPEG q85 ≤1600px →
   сервер `to_jpeg_b64` пережимал ЕЩЁ раз (q85). Двойное lossy-сжатие убивало штрихи рукописи →
   OCR вернул 40 слов на всю страницу. Дальше — каскад: правило объёма обнуляло все критерии (0/8),
   ошибки без фрагмента в тексте выбрасывались как «выдуманные» (нарушение обработки ошибок при
   недостатке слов в тексте), привязка ошибок к фото не строилась.
4. **Вёрстка PDF.** Движок html (Chromium) — дефект в раскладке макета; блок выше страницы не разбивается
   (перенос только если текущая страница не пуста) и вылезает за 296mm, наезжая на контейнеры.

# 001 · ИИ-проверка: мок-разбор ошибок вместо живого + съехавшие маркеры на фото

Статус: **исправлено** — см. §4 «Исправление».
Дата: 2026-10-24. Раздел «ИИ-проверка». Затронуты обе копии кода: `dev/` и `prod/`.

---

## 1. Симптомы (как их видит пользователь)

Пользователь сфотографировал работу и получил разбор:

1. **Ошибки — заглушки, их текст не совпадает с фото.** В разборе фигурируют слова и фразы,
   которых нет на снятой работе («влеяния», «в течении», «более лучше» и т.п.).
2. **Маркеры ошибок съехали: они внизу экрана, а не поверх превью фото.** Вместо выделения
   фрагментов на снимке — кружки в случайных местах (в т.ч. у нижнего края).

Ожидаемое поведение: разбор строится по **реальному** тексту фото (OCR), ошибки и их
обоснования соответствуют написанному учеником, маркеры стоят **ровно над словами-ошибками**
на каждом снимке.

---

## 2. Причина (точные адреса в коде)

**Главная причина — отладочный переключатель фронтенда.**
`dev/bot-mini-app/docs/index.html`, строка ~2742 (до правки):

```js
const EC_MOCK=true;   /* ОТЛАДКА ИНТЕРФЕЙСА: разбор — локальный мок поверх реальных фото … */
```

Пока `EC_MOCK=true`, функции `ecUpload()` и `ecRun()` **не обращались к API вовсе**
(`if(EC_MOCK){ecMockRun();return}`) и подставляли локальные мок-данные
(`EC_MOK_TEXT`, `EC_MOK_ERRORS`, `EC_MOK_CRIT`). Это была заглушка для отладки интерфейса,
которая осталась включённой в боевой сборке.

**Почему маркеры «съехали».** Мок-ошибки несут свои демо-координаты (`page/x/y` — проценты
от фото из макета). Их натягивали на **настоящие** фото пользователя: координаты, вычисленные
для другого изображения, естественно не совпадают с текстом ученика и оказываются в случайных
местах, в том числе у нижнего края.

**Сопутствующая проблема прозрачности.** Демо-разбор на экране ничем не отличался от настоящего:
данные-заглушки выдавались за результат проверки — без пометки о том, что фото никуда не
отправлялись.

---

## 3. Что подтвердило диагноз

- Живой пайплайн на бэкенде при этом работал корректно: локальный сквозной прогон
  (реальный Yandex Vision OCR + лёгкая Kimi) давал настоящую транскрипцию фото, 7 ошибок
  с источниками («Розенталь, §…», «Критерии ФИПИ, К…»), координаты из разметки OCR и балл,
  посчитанный кодом. То есть проблема была **не в пайплайне, а в том, что экран его не вызывал**.
- Тексты мок-ошибок (`EC_MOK_ERRORS`) буквально совпадали с тем, что видел пользователь.

---

## 4. Исправление

Коммит `98009a5` (dev+prod):

1. **`EC_MOCK=false`** — экран разбора берёт данные из настоящего стрима
   `/api/essay_check/run` (OCR фото → анализ Кими → координаты ошибок из разметки OCR
   именно этого фото).
2. **Баннер демо-режима.** Результат демо-пайплайна помечается флагом `demo`
   (`essaycheck.py`), фронт показывает баннер:
   «⚠️ Демо-режим: разбор демонстрационный, фото не отправлялись в ИИ».
   Демо-данные больше не могут выдаваться за настоящие.
3. Заодно исправлена авторизация `fipicache` (fetch критериев ФИПИ с fipi.ru) — см. коммит.

Дополнительно (коммит `03-2026-10-24`): контрактный тест закрепляет, что в боевой сборке
`EC_MOCK=false` и баннер демо-режима присутствует, — случайное возвращение заглушки
теперь ломает тесты.

## 6. Урок

Не выдавать проверку пайплайна за проверку продукта: сквозной тест API не подтверждает
поведение экрана. Перед статусом «готово» — сценарий именно в интерфейсе (или headless-рендер),
плюс явные пометки демо-данных в UI.

# 003 · ИИ-проверка: разбор выдавался демо-данными, фото не уходили в ИИ (APK/мини-апп)

Статус: **исправлено** — см. §4 «Исправление».
Дата: 2026-10-24. Раздел «ИИ-проверка». Затронуты обе копии кода: `dev/` и `prod/`.
Доказательства: `003-scrin-1.jpeg`, `003-scrin-2.jpeg`.

---

## 1. Симптомы (как их видит пользователь)

Пользователь сфотографировал рукописную работу (конспект про вакансии/резюме) и получил разбор:

1. **Красный баннер на экране разбора:** «⚠ Демо-режим: разбор демонстрационный,
   фото не отправлялись в ИИ» (`003-scrin-1.jpeg`).
2. **Ошибки — заглушки, их нет на фото.** В разборе значатся «влеяния», «в течении»,
   «Во первых», «более лучше», «по этому», «Таким образом автор» — слова из демонстрационного
   сочинения о книге, которых на снимке ученика нет вовсе.
3. **Маркеры ошибок съехали** — пины (№1, 3, 4, 5, 6, 7) стоят скоплением внизу снимка,
   а не над словами-ошибками (`003-scrin-2.jpeg`).

Ожидаемое поведение: фото уходят в Yandex Vision OCR + Кими, ошибки находятся по реальному
тексту ученика, маркеры стоят над словами-ошибками.

## 2. Причина (точные адреса в коде)

**Сервис работал в демо-режиме: в процессе не был выставлен `EC_LIVE=1`.**

`prod/bot-mini-app/essaycheck.py` (и зеркально `dev/…`), строка 28 (до правки):

```python
DEMO = os.getenv("EC_LIVE", "").strip() != "1"   # выключается только командой владельца (EC_LIVE=1)
```

Демо-режим был **включён по умолчанию** и выключался только точным значением `EC_LIVE="1"`
(`"0"`, `"true"`, пусто — всё оставалось в демо). Пока `DEMO` истинно, `run()` (строка 351)
вообще не ходил в API:

```python
if DEMO:                                   # фото не уходят в API — только локальный демо-разбор
    async for ev in _demo(w, t):
```

`_demo()` возвращал `_result({"errors": DEMO_ERRORS, …})` с `res["demo"] = True` — фронт по
этому флагу показывал баннер «Демо-режим» (`docs/index.html`, строка 3137 до правки).

Цепочка на скринах: «Готово» → upload/`run` → `essaycheck.DEMO == True` → `_demo()`
→ на **настоящие** фото ученика натягивались `DEMO_ERRORS` со своими демо-координатами
`page/x/y` (строки 40–60: 7 ошибок из макета `dev/mockups/essay-check.html`) → координаты,
вычисленные для другого изображения, не совпадали с текстом ученика и пины оказывались внизу
снимка. Это **тот же визуальный баг, что и в 001**, но источник моков теперь был не фронт
(`EC_MOCK` уже `false`), а бэкенд-демо.

**Почему `EC_LIVE` не действовал.** В `render.yaml` переменная объявлена, но:
- **`YANDEX_API_KEY` отсутствовал в blueprint вообще** (в `envVars` его не было — лишь
  комментарий «вводится в панели»). Даже с `EC_LIVE=1` боевой пайплайн без него не стартует:
  `bot.py:2645` отдаёт `{"t":"off"}` — окружение сервиса просто не было доведено до боевого.
- Переменные с `sync: false` вводятся вручную при синхронизации blueprint — пока значения
  не введены, изменения не применяются (предупреждение в конце `render.yaml`).
- На варианте деплоя через `deploy.sh` + `docker-compose.yml` в `.env.example` по умолчанию
  стояло `EC_LIVE=0` — копия примера давала демо.

**Почему это не было покрыто тестами.** `tests/test_apk_shell.py:34` как раз охранял этот
случай (`"Демо-режим" not in html`), но после коммита `bfb41e0` баннер осознанно добавили
в `docs/index.html`, а тест не обновили — контракт был красный и защиту не обеспечивал.

## 3. Что подтвердило диагноз

- Баннер «фото не отправлялись в ИИ» — прямой вывод `result.demo === true`, который ставил
  только `_demo()`.
- Тексты ошибок буквально совпадали с `DEMO_ERRORS`/`DEMO_TEXT` из `essaycheck.py`
  («влеяния», «в течении», «Во первых», «более лучше», «по этому») — на фото ученика
  (конспект про вакансии) этих слов нет.
- Сквозной прогон боевого пайплайна на реальных ключах (Yandex OCR → Кими → координаты)
  выдаёт настоящий разбор с `demo` отсутствующим — то есть проблема была не в пайплайне.
- Локальный прогон переключателя: `EC_LIVE='' / '0' / 'true' → DEMO=True`.

## 4. Исправление

По решению владельца **демо-режим удалён полностью: приложение работает только с настоящими
данными** — подмена разбора заглушками больше невозможна в принципе.

1. **Окружение прод-сервиса** (`tutor-bot`, Render): `EC_LIVE=1`, `YANDEX_API_KEY`
   (ключ Yandex Cloud для Vision OCR), `KIMI_API_KEY` — проверено через Render API,
   боевой пайплайн прогнан на живых ключах (OCR: 199 символов, 70 боксов с координатами).
2. **`essaycheck.py` (dev+prod)**: удалены `DEMO`/`DEMO_DELAY`, демо-данные
   (`DEMO_ERRORS`/`DEMO_TEXT`/`DEMO_TASK`/`DEMO_CRITERIA`/`DEMO_RECS`) и `_demo()`;
   `run()` всегда идёт в Yandex Vision + Кими.
3. **`bot.py` (dev+prod)**: `off`-состояние теперь только про ключи — нет `KIMI_API_KEY`
   или `YANDEX_API_KEY` → `{"t":"off"}` (фронт честно говорит, что ИИ не подключён).
4. **`docs/index.html` (dev+prod)**: удалены баннер «Демо-режим» (`.ec-demo`) и весь
   отладочный мок (`EC_MOCK`, `EC_MOK_*`, `ecMockRes`/`ecMockRun`); `ecNrm` больше не
   пропускает флаг `demo`.
5. **`render.yaml` / `.env.example`**: удалена переменная `EC_LIVE` (больше не нужна),
   `YANDEX_API_KEY` добавлен в blueprint обоих сервисов (`sync: false`, как `KIMI_API_KEY`).
6. **Тесты**: удалены демо-кейсы (`test_essay_check.py` §9, демо-оверлей); контракты
   `test_frontend_contract.py` и `test_apk_shell.py` теперь требуют **отсутствия** моков
   и демо-баннеров в `index.html`; `test_essaycheck_live.py` переведён на живой путь.

## 5. Проверка после исправления

- Весь набор тестов зелёный: `tests/test_*.py` (включая `test_release_contract` —
  dev и prod идентичны).
- Сквозной прогон боевого пайплайна (реальные ключи, реальное фото): стадии
  `status → think → done`, `demo`-флага нет, ошибки и координаты — по фактическому тексту.
- На экране разбора нет баннеров демо-режима — разбор приходит только из
  `/api/essay_check/run`, при отсутствии ключей — состояние «ИИ не подключён» (`off`).

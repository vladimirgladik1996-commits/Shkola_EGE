# 004 · ИИ-проверка: падение прода — разбор недоверенного ответа модели, второй статус поверх стрима, заморозка event loop

Статус: **исправлено** — см. §3 «Исправление».
Дата: 2026-10-24. Раздел «ИИ-проверка» (затронут и «Чат с ИИ» — общий дефект стримов).
Затронуты обе копии кода: `dev/` и `prod/`. Прод: `tutor-bot` (Render, `prod/bot-mini-app`).

---

## 1. Симптомы (как их видит пользователь)

1. **Проверка обрывается на середине:** «Проверка не завершилась» + «Повторить» —
   после того, как Вишенка уже читала фото и думала.
2. **В клиенте буквально это** (лог WebView / консоль):

   ```
   Invalid character in chunk size:
    b'HTTP/1.1 400 Bad Request'
   ```

3. **Бот и API замирают целиком** на несколько секунд — не отвечают ни «ИИ-проверка»,
   ни другие разделы, потом сервис сам перезапускается (Render: health-check `/`
   не проходит за `HEALTHCHECK --timeout=5s` из Dockerfile).

## 2. Причины (точные адреса в коде)

Три независимых дефекта сливались в одно «сервис упал».

### 2.1. Ответ модели — недоверенные данные, а код считал его строкой

`essaycheck.py`. Модель присылает, например, `"found": 2024` (число — когда фрагмент
работы это цифра/год) или объект; `"errors"` — не список; `"page": inf`.

- `_norm()` делал `(s or "").lower()` → **AttributeError** на не-строке.
- Проверка «found должен быть строкой» есть только в `_result()`, а `_bind_coords()`
  вызывается **раньше** и получает сырое значение.
- `for e in a.get("errors") or []` по не-списку → **TypeError: 'int' object is not iterable**.
- `_result()`, `int(v)` при `page: inf` → **OverflowError**; `_num()` ловил только
  `TypeError`/`ValueError`.
- `_lev1()` имел off-by-one: `range(lb)` вместо `len(b)` **после** обмена аргументов —
  удаление последнего символа не находилось, часть ошибок оставалась без оверлея на фото.

### 2.2. Исключение после `resp.prepare()` рвало HTTP-соединение

`bot.py`, `guarded()`. NDJSON-стрим уже начал отдаваться → пайплайн падал → `guarded`
ловил ошибку и возвращал **новый** `web.Response(400)`. aiohttp дописывал второй
HTTP-статус поверх уже начатого chunked-тела — клиент получал «Invalid character in
chunk size: b'HTTP/1.1 400 Bad Request'». Для reverse-proxy Render это выглядит как
мёртвый бэкенд. Тот же дефект был у `/api/chat`.

### 2.3. Поиск координат морозил весь процесс — это и есть «сервис упал»

`essaycheck.py`, `_bind_coords()`: перебор O(страницы × ошибки × фрагмент) синхронно
в событийном цикле. Замер на 12 фото / 6 страниц / 60 ошибок с ненайденными
фрагментами: **8.01 с** полной остановки бота и API → HEALTHCHECK (5 с) не проходит →
Render перезапускает сервис.

## 3. Исправление (три коммита в `main`, dev и prod синхронно)

**`0c3b838` — разбор ответа модели больше не может обвалить проверку:**
- `_norm()` принимает что угодно: не-строка → пустой фрагмент («не найден»);
- `_as_list()` — итерируем только настоящие списки (`errors`/`criteria`/`recommendations`);
- `_finite()` + `_num()` ловит `OverflowError`: `inf`/`nan`/`bool` в координатах — не число;
- `_lev1()` — off-by-one починен.

**`6909d54` — поиск координат больше не морозит бота и API:**
- `_near()` — дешёвый звуковой префильтр перед `_lev1` (не отбрасывает совпадений);
- поиск вынесен из event loop: `await asyncio.to_thread(_bind_coords, a, pages)`.

**`c668d25` — стрим, который уже начался, нельзя «дописать» вторым статусом:**
- `bot._stream_fail()`: сбой после `prepare()` → `{"t":"fail","why":"net"}` + штатный
  конец тела (фронт: «Проверка не завершилась» + «Повторить»);
- `guarded` — все ветки исключений (400 / HTTPException / 500) идут через `_stream_fail`,
  дефект закрыт и для `/api/chat`, и для будущих стримов;
- ошибка **до** стрима — обычный HTTP-код, контракт не менялся.

## 4. Проверка

- **Регрессия воспроизведена:** новые тесты на неисправленном коде падают ровно с тем,
  что видит пользователь — `TypeError: 'int' object is not iterable` и
  `Invalid character in chunk size: b'HTTP/1.1 400 Bad Request'`.
- `tests/test_essaycheck_parse.py`: фаззер разбора модели — 682+ комбинации мусорных
  полей → 0 падений; `_near`-звук (3000 случайных пар); `_lev1` (вставка/замена/удаление,
  включая последний символ).
- `tests/test_stream_fail.py`: оба стрима (`/api/essay_check/run`, `/api/chat`) при сбое
  после `prepare()` → `200` + `{"t":"fail","why":"net"}` + валидный конец NDJSON; ошибка
  до стрима → обычный `400`.
- `_bind_coords`: 6 страниц × 40 ошибок с ненайденными фрагментами — **3.56 с → 0.99 с**
  на тестовом стенде (8.01 с → 0.58 с на стенде разбора инцидента), и это больше
  не держит event loop (`asyncio.to_thread`).
- Полный прогон `tests/test_*.py` в `dev/` и `prod/` — зелёный, кроме двух прежних
  падений `test_materials.py` / `test_chat_materials.py` (контрактные строки раздела
  «Материалы» — существуют до правки, вынесены отдельными инцидентами в `bug-reports/002`).
  `test_release_contract.py` проходит — копии идентичны.

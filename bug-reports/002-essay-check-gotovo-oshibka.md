# 002 · ИИ-проверка: «Готово» на экране фото выдаёт ошибку и не пускает дальше (APK)

Статус: **исправлено** — см. §4 «Исправление».
Дата: 2026-10-24. Раздел «ИИ-проверка». Затронуты обе копии кода: `dev/` и `prod/`.

---

## 1. Симптомы (как их видит пользователь)

В разделе «ИИ-проверка» в standalone-приложении (APK):

1. После нажатия «Готово» на экране фото появляется ошибка («Не получилось, попробуйте ещё раз»)
   и экран не переходит дальше — распознавание текста и разбор ошибок не запускаются вовсе.
2. Как следствие «не работают» и OCR, и диагностика ошибок: запрос до пайплайна просто не доходит.

Ожидаемое поведение: «Готово» принимает фото, запускает проверку и выдаёт разбор —
в точности как в Telegram-мини-аппе.

## 2. Причина (точные адреса в коде)

**Загрузка и запуск проверки отвергали standalone-вход (APK).**
Пользователь APK авторизуется токеном X-Session с `tg_id=0` (`auth.STANDALONE_UID`,
см. `auth.py` — «standalone-вход (APK вне Telegram): … API-токен (tg_id=0)»).
А два обработчика требовали строго положительный идентификатор:

`prod/bot-mini-app/bot.py` (до правки, = `dev/…`):

| Что | Строка |
|---|---|
| `api_essay_check_upload` — `if not isinstance(uid, int) or uid <= 0 …` → 400 | 2591 |
| `api_essay_check_run` — `if not rec or … uid <= 0: raise ValueError` → 400 | 2624 |

Цепочка: «Готово» → `POST /api/essay_check/upload` с `X-Session` → `user_id()` возвращает `0`
→ `uid <= 0` → **400 `{"error":"bad"}`** → фронт (`ecUpload`, `api()`) показывает
«Не получилось, попробуйте ещё раз» и остаётся на экране фото. Запрос до OCR/Kimi не доходит.

**Почему баг не был виден раньше.** Сохранение и история проверок уже принимали `uid 0`
(функция `ec_uid`, строка 2681: «сохранение и история доступны и standalone-входу (uid 0)») —
а загрузка и запуск (пуши 4–5) — нет. Контрактные тесты (`tests/test_essay_check.py`) гоняли API
только с Telegram-подписью `X-Init` (tg_id 42/77) и не покрывали standalone-путь —
в Telegram-мини-аппе всё работало, и сбой проявлялся только в APK.

## 3. Что подтвердило диагноз

- Регрессионный тест (§5) на **исходном** коде: `POST /api/essay_check/upload` с валидным
  standalone-токеном → `400 {'error': 'bad'}` — ровно то, что видит пользователь после «Готово».
- Тот же запрос с Telegram-подписью (`X-Init`) проходил — поэтому весь остальной набор
  тестов «ИИ-проверки» был зелёным.
- Живой пайплайн (OCR → анализ → координаты) при этом исправен: после правки сквозной прогон
  через тот же HTTP-контур выдаёт нормализованный разбор (`done.result`) и для `uid 0`.

## 4. Исправление

Правятся обе копии: `dev/bot-mini-app/bot.py` = `prod/bot-mini-app/bot.py`.

1. Единый helper `ec_uid()` (принимает `uid >= 0`, то есть и standalone `0`) поднят выше
   и используется во **всех** ручках «ИИ-проверки»: `upload`, `run`, `save`, `history`, `load`.
2. `api_essay_check_upload` / `api_essay_check_run`: проверка `uid <= 0` заменена на `ec_uid(request)`.
   Поведение для прочих случаев не меняется: без входа — 403 (`guarded`), мусор — 400,
   чужой сеанс — 403 (владелец сеанса по-прежнему проверяется: `rec[0] != uid`).
3. `tests/test_essay_check.py` — новый раздел 10 «standalone-вход (APK, tg_id=0)»:
   «Готово» принимает фото, `run` выдаёт разбор — как из Telegram.

## 5. Проверка

- Новый тест на исходном коде падает с `(400, {'error': 'bad'})` — баг воспроизводится;
  после правки проходит: «standalone (APK, tg_id=0): „Готово“ принимает фото, run выдаёт разбор».
- Полный прогон `python3 tests/test_*.py` в `dev/` и `prod/`: `test_essay_check.py`,
  `test_essay_history.py`, `test_essaycheck_live.py`, `test_yavision.py`, `test_think_relay.py`
  и остальные — зелёные.
- ⚠️ Три падения существуют **до правки и не связаны с ней** (проверено на чистом HEAD):
  `test_materials.py`, `test_chat_materials.py` (контрактные строки фронта раздела «Материалы»),
  `test_apk_shell.py`. Вынесены отдельными инцидентами.

## 6. Урок

`uid == 0` — полноценный пользователь (APK), а не «нет пользователя». Любая новая ручка API,
которая работает с данными пользователя, должна идти через `ec_uid()`-семантику и иметь
тест на standalone-путь — иначе фича живёт только в Telegram и «случайно» ломается в APK.

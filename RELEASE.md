# RELEASE.md — как устроены файлы и релизы, чтобы ничего не пропадало

Правила ниже закрывают все известные способы «потерять файлы»: модуль, не попавший в
образ Docker; ключ подписи, оставшийся на одной машине; APK, затёртый новой сборкой;
разъехавшиеся копии dev и prod.

---

## 2. Железное правило: образ Docker собирается целиком

`Dockerfile` делает `COPY . .`, а всё лишнее перечислено в `.dockerignore`
(секреты, `data/`, `backups/`, ключи, `tests/`).

**Почему так:** раньше Dockerfile перечислял файлы по одному (`COPY bot.py auth.py ./`),
и каждый новый модуль молча не попадал в релиз — приложение падало при старте.
Теперь любой новый файл попадает в образ автоматически.

Контроль — тест `tests/test_release_contract.py`:
- `COPY . .` на месте, `.dockerignore` исключает секреты и данные;
- все модули, которые импортирует `bot.py`, лежат рядом;
- мини-апп (`docs/index.html`) и шрифты на месте;
- код `dev/` и `prod/` идентичен (разрешены только `.env.example`, `DEPLOY.md`, `deploy.sh`);
- исходники и APK в git, номер версии корректен, ключ подписи в git не попадает.

## 3. Порядок релиза

1. Прогнать тесты в обеих средах: `cd dev/bot-mini-app && python3 tests/test_*.py` (и так же в `prod/`).
2. Если менялся Android: `sh apk/build.sh` — новый APK ляжет в `apk/releases/` и не затрёт прошлые.
3. Правки кода переносим в **обе** копии (`dev/` и `prod/`) — тест сам остановит релиз при расхождении.
4. Коммит + тег `vX.Y` + push. Render соберёт и выкатит сам (`autoDeploy`).
5. Данные при релизе не теряются: `tutor.db` лежит на постоянном диске `/app/data`
   (план `0.5c-512mb`), у Render есть ежедневный снапшот диска.

## 4. Ключ подписи APK — чтобы не потерять (это уже случилось)

`keystore.jks` — это ключ, без которого нельзя выпустить обновление «поверх»
установленного приложения. В публичный git его класть нельзя, но и хранить на одной
машине опасно: ключ уже потерялся именно так.

Решение — **зашифрованная копия в git**:

```bash
openssl enc -aes-256-cbc -pbkdf2 -salt -in dev/apk/keystore.jks   -out dev/apk/keystore.jks.enc
openssl enc -aes-256-cbc -pbkdf2 -salt -in dev/apk/keystore.pass -out dev/apk/keystore.pass.enc
```

Файлы `*.enc` коммитятся (без пароля они бесполезны), пароль шифрования храним у себя —
в менеджере паролей, не в репозитории. Восстановление:

```bash
openssl enc -d -aes-256-cbc -pbkdf2 -in dev/apk/keystore.jks.enc -out dev/apk/keystore.jks
```

Если ключ всё-таки потерян: новое приложение ставится только после удаления старого.
Данные кабинета живут на сервере, а не в телефоне, поэтому потерь нет — только лишний шаг.

**Отпечаток ключа закреплён в `apk-sign/SHA256.txt`.** CI сверяет отпечаток подписанного
APK с этим файлом и останавливает сборку, если ключ вдруг другой. Это ловит сценарий
«keystore не открылся — CI выпустил новый ключ»: без проверки такие APK молча уходят
в релиз и перестают обновлять установленные приложения (так уже было — старые APK
подписаны другими ключами). Осознанная смена ключа = заменить отпечаток в
`apk-sign/SHA256.txt` тем же коммитом и предупредить пользователей о переустановке.

## 5. Что защищает от каждого вида потерь

| Риск | Защита |
|---|---|
| новый модуль/файл не попал в образ | `COPY . .` + тест контракта |
| секрет или база попали в образ | `.dockerignore` + тест |
| dev и prod разъехались | тест идентичности деревьев |
| APK затёрт новой сборкой | `apk/releases/kabinet-repetitora-<versionCode>.apk` |
| потерян ключ подписи | зашифрованный дубль `keystore.*.enc` (п. 4) |
| подпись без чьего-либо ведома сменила ключ | закреплённый отпечаток `apk-sign/SHA256.txt` + проверка в CI |
| потеряна база данных | постоянный диск Render + снапшоты + бэкапы `deploy.sh` |
| релиз сломал прод | тесты до push + `autoDeploy` с откатом через Rollback в Render |

## 6. План реорганизации (отдельным релизом)

Сейчас код продублирован в `dev/` и `prod/` — это главный источник расхождений.
Целевая схема:

```
app/            ← единый код бота + мини-аппа (одна копия)
envs/dev/       ← .env, настройки окружения
envs/prod/      ← .env, настройки окружения
android/        ← исходники APK
artifacts/      ← собранные APK по версиям
tests/          ← тесты (общие)
```

Переезд требует правки `render.yaml` (rootDir), `deploy.sh` и документации —
делать его нужно отдельным релизом, когда текущая версия стабильна.

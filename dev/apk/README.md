# APK (DEV) — Android-приложение «Надежда DEV»

WebView-обёртка того же кабинета, что и мини-апп. Отличия этой (dev) сборки:

- подсказка по умолчанию — dev-адрес `https://tutor-bot-dev.onrender.com/`
  (адрес можно сменить в приложении: долгое нажатие → «Сменить адрес сервера»);
- имя приложения — «Надежда DEV», `versionName` — `1.0-dev`;
- подписан debug-ключом, который `build.sh` создаёт автоматически и дальше
  хранит в `keystore.jks` рядом с собой (см. ниже — без постоянного ключа
  обновление поверх старого APK невозможно);

## Сборка

Нужны JDK 17+ и Android SDK (build-tools 34.0.0, platform android-34).
Тулчейн ищется рядом с этой папкой: `../jdk` и `../android-sdk`.
Другое расположение:

```bash
export ANDROID_BUILD_ROOT=/путь/к/каталогу   # внутри — jdk/ и android-sdk/
sh build.sh                                   # на выходе: kabinet-repetitora.apk
```

Готовый APK появится в этой папке. Прод-версия приложения (с рабочим
адресом и release-подписью) — в `../../prod/apk/`.

## Подпись и обновления

`build.sh` создаёт локальный ключ `keystore.jks` **рядом с собой** и дальше
использует тот же ключ (`keystore.jks` в `.gitignore`, в git не попадает).
Android ставит обновление поверх старого APK только при совпадении подписи
и не меньшем `versionCode`, поэтому:

- **сохраните `keystore.jks`** — потеря ключа = удаление приложения перед каждой
  новой установкой (ключ в `build/` стирался при каждой пересборке);
- свой ключ и пароль: `ANDROID_KEYSTORE=... KEYSTORE_PASS=... sh build.sh`;
- `versionCode` растёт с каждой сборкой (файл `version-code`, лежит в git).
  Принудительно: `VERSION_CODE=7 sh build.sh`.
